# Notes for Claude

Read [docs/REPO_GUIDE.md](docs/REPO_GUIDE.md) first: it describes the pages, code layout, data jobs, schedules, methodology, colour conventions and maintenance tasks.

**Keep the guide current.** Whenever a change affects anything the guide describes (files or their roles, data sources, workflows or schedules, safeguards, methodology, colour conventions, maintenance tasks), update `docs/REPO_GUIDE.md` in the same commit and add a dated line to its change log. Keep the README's file tree in sync too.

Ground rules:
- The repository is public. Keep the nine stocks of `index.html` anonymised (no real names or tickers), and put no personal details (e-mail addresses, account IDs) in files.
- `data/dax40.js`, `data/dax40_prices.csv`, `data/markets/*` and the `live-data` and `live-markets` branches are generated by the workflows; don't edit them by hand.
- `markets.html` (Market View), the five European market pages (`cac40.html` … `ftse100.html`) and the Market View navigation in `index.html` and `dax.html` are generated: change `python/markets.py` or the templates in `python/make_market_pages.py`, then run `python python/make_market_pages.py`.
- Prefer real data over simulations, readable green-to-red colour scales, and an on-page explanation for every metric.
- `python/build_dax40.py` and `python/build_market.py` must never publish data older than what is online; failed downloads keep the published file.

Working in a Claude session:
- Fetch the live branches with `git fetch --depth 1 origin +refs/heads/live-data:refs/remotes/origin/live-data` (and the same for `live-markets`); they are force-pushed.
- `gh run list` / `gh run view <id> --log` / `gh workflow run <file> --ref main` work for checking and starting the jobs. Sites such as github.io and Yahoo may be unreachable from the sandbox, so verify through the commits, branches and run logs the jobs produce.
- For visual checks, use Playwright with the local Chrome and serve the CDN libraries from local npm copies.
